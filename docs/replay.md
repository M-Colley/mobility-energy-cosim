# Replay: SUMO once, CityLearn many

`mecosim export-citylearn` runs the live co-simulation once and writes the mobility it produced as a CityLearn
dataset. `CityLearnEnv(schema.json)` then replays it at CityLearn speed, without mecosim and without SUMO. Use it to
train or evaluate energy controllers on a fixed mobility trace.

```console
mecosim export-citylearn examples/two_zone_demo/scenario.yaml --policy greedy_deficit --seeds 1,2,3 --out output/export
```

Each seed writes `output/export/seed_<n>/`: `schema.json`, the building files, one `charger_<id>.csv` per external
charger, `actions.csv` (the charger actions of the live run) and `live_metrics.json`. Requires CityLearn with trace
replay (branch `feat/mobility-trace-replay`, see its `docs/mobility_provider.md`).

```python
from citylearn.citylearn import CityLearnEnv

env = CityLearnEnv("output/export/seed_1/schema.json", central_agent=True)
```

## What is recorded

The orchestrator is CityLearn's mobility provider and writes the charger rows through `env.mobility`. The exporter
keeps the rows CityLearn holds at the end of the run and the vehicle SOC at the start of every step:

| Charger file column | Source |
|---|---|
| `electric_vehicle_charger_state`, `_id`, `_session_id`, `_departure_time`, `_required_soc_departure`, `_estimated_arrival_time`, `_estimated_soc_arrival` | `connect`, `incoming`, `away` |
| `electric_vehicle_connected_seconds`, `electric_vehicle_connected_since_seconds`, `electric_vehicle_departure_seconds`, `electric_vehicle_discharge_soc_floor` | `connect(...)` |
| `electric_vehicle_current_soc` | absolute SOC at arrival (fallback) |
| `electric_vehicle_trip_energy_kwh` | (SOC at the previous departure - arrival SOC) x battery capacity, on the first row of each session |

With the trip energy an arrival SOC follows the SOC the vehicle left with. A replay with other charger actions then
carries the effect of earlier charging into the next session, as the live run does. The first session starts from the
vehicle's initial SOC. Away from the chargers a vehicle keeps its SOC in the replay; the driving consumption is
applied at the next arrival.

## Equivalence

For the same charger actions, a live run and the replay of its export give the same charger energies and CityLearn
KPIs to 1e-9 relative (`tests/test_export_citylearn.py`, and `examples/two_zone_demo/replay_check.py` for the demo).

## Limit

Replay is valid only when the controller does not change the mobility. Mobility reacts to energy in the live run:
the SOC of a vehicle enters the policy's decisions (energy stops, reserve, dispatch) and the traffic. The replay
keeps the recorded decisions. If a controller's actions change what the vehicles do, the replay is wrong in
proportion to that influence. A controller that sets only building and charger power for the recorded sessions is
inside the limit. A controller that dispatches vehicles or chooses the stops is not; use the live co-simulation.

`examples/two_zone_demo/replay_check.py` quantifies the divergence for changed charger actions (see the numbers in
the section below, regenerated by the script).
